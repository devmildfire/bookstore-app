# TypeScript Conventions

This is a strict TypeScript project (`"strict": true` in `tsconfig.json`). All new files must be TypeScript.

## General Principles

- Every new file is `.ts` or `.tsx` — no `.js` files
- Keep types close to their usage; avoid large disconnected type-only files unless the type is reused widely
- Prefer explicit over implicit — when inference is unclear, annotate

## Type Design

- Use `type` for object shapes, unions, and mapped types
- Use `interface` only when extension or declaration merging is intentionally needed
- Export types from the feature/entity module first; promote to `src/types/` only when genuinely shared across features

```ts
// good — local to the feature
type BookCardProps = {
  id: string
  title: string
  price: number
  coverUrl: string | null
}

// good — shared entity interface
export type Book = {
  id: string
  title: string
  authorId: string
  price: number
}
```

## `any` Policy

- Never use `any` in new code
- Use `unknown` at unsafe boundaries (Supabase responses before normalization, third-party payloads), then narrow:

```ts
function normalize(raw: unknown): Book {
  if (!isRawBook(raw)) throw new Error('Unexpected shape')
  return { id: raw.id, title: raw.title, ... }
}
```

- If `any` is genuinely unavoidable, keep it local and add a comment explaining why

## Function and API Boundaries

- Add explicit parameter types and return types for all exported functions and hooks
- Treat Supabase query results as untrusted before they pass through `normalize.ts`
- Use Zod at form validation boundaries and anywhere user input enters the system

## React + TypeScript

- Type component props explicitly — no implicit `{}` props
- Keep prop types in the same file as the component unless they are reused elsewhere
- Use discriminated unions for UI state variants instead of loosely typed string flags:

```ts
// good
type OrderStatus =
  | { kind: 'idle' }
  | { kind: 'loading' }
  | { kind: 'success'; orderId: string }
  | { kind: 'error'; message: string }

// bad
type OrderStatus = {
  loading: boolean
  error: string | null
  orderId: string | null
}
```

## Import Style

- Always use `import type` when importing only types:
  ```ts
  import type { Book } from '@/entities/book/client'
  ```
- Use the `@/*` path alias for internal imports
- Do not duplicate existing domain types — extend them

## Enums

- Prefer `const` object + `typeof` union over TypeScript `enum`:

```ts
// good
export const BookFormat = {
  PDF: 'pdf',
  EPUB: 'epub',
  MOBI: 'mobi',
} as const
export type BookFormat = (typeof BookFormat)[keyof typeof BookFormat]

// avoid
enum BookFormat { PDF = 'pdf', EPUB = 'epub', MOBI = 'mobi' }
```

## Supabase Types

- Generated types live in `src/types/supabase.ts` — do not edit this file manually
- Derive client-facing types from generated types using `QueryData<typeof query>` or manual picks
- Regenerate after any schema change using the command in `AGENTS.md`
