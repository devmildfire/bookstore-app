# Chtivo

Новый сайт Чтива

> Содержимое ниже устарело (описывает старую Pages-Router архитектуру: `pages/api`,
> `FC`-тип, `styles.ts`, `models/` MobX-стор и т.п.). Актуальная архитектура, стек и
> команды (включая регенерацию типов Supabase) — в [AGENTS.md](AGENTS.md).


## Getting Started

First, run the development server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

The `pages/api` directory is mapped to `/api/*`. Files in this directory are treated as [API routes](https://nextjs.org/docs/api-routes/introduction) instead of React pages.

## Структура

### Страницы

0. Все страницы хранятся в папке pages
1. Все страницы хранятся в папках и экспортируются через index файл
2. На вложенные страницы создаются подпапки

### Asset'ы

0. asset'ы хранятся в директории src/assets, кроме шрифтов, они хранятся в public/fonts
1. Все иконки помещаются в папку assets/icons и создается компонент для ее использования
2. Все статические картинки помещаются в папку assets/images и импортируются в нужный файл

### Компоненты

0. Все компоненты хранятся в папке components
1. Для каждого компонента создается своя папка в которой должно быть: одноименный файл с компонентом, файл со стилями styles.ts, экспортирующий файл index.ts и опциональный types.ts с общими для компонента и стилей типами
2. Компоненты группируются по папкам-страницам
3. Компоненты, что могут быть переиспользованны помещаются в папку components/Common
4. Глобальные компоненты просто помещаются в директорию
5. Все Popup'ы помещаются в папку components/Popups
6. Дочерние компоненты специфичные для конкретного компонента располагаются в директории родителя

### Константы

0. Константы располагаются в директории consts
1. В директории создается файл по области применения констант, из которого они экспортируются именным образом вместе с интерфейсом, если это нужно

### Контексты

0. Все контексты лежат в одноименных директориях в папке contexts
1. Файл context экспортирует именным образом интерфейс контекста и по умолчанию объект контекста, если он один
2. Файл provider экспортирует провайдер для контекста по умолчанию
3. Файл index реэкспортирует контексты, провайдера и интерфейсы

### Хуки

0. Хуки хранятся в папке hooks
1. Хуки хранятся в одноименных файлах
2. Хук экспортируется по умолчанию, а типы, если таковые имеются, именным способом

### Сетки

0. Все сетки лежат в одноименных папках
1. Сетки подчиняются правилам компонент 1 и стилям компонент

### Моки

0. Моковые данные хранятся в папке mocks

### Модели

0. Стор хранится в папке models
1. Для каждой части стора создается подпапка с ее названием
2. Каждая папка части стора содержит index файл, что реэкспортирует все, types, содержащая типы для части и файл store и/или api для стора и/или апи

### Глобальные стили

0. Глобальные стили хранятся в папке styles
1. Глобальные стили подключаются в файл global.css, который потом подключается в корень проета

### Типы

0. Все общие типы хранятся в папке types
1. Типы хранятся в одноименных или группирующих по названию файлах
2. Типы экспортируются именным способом

### Утилиты

0. Все утилиты хранятся в папке utils
1. Утилиты экспортируются по умолчанию

## Силь кода

1. Стили для страниц прописываются в файле страницы ниже компонента
2. Все стили прописываются в файле styles.ts и экспортируются по именам
3. Компоненты создаются с использованием типа FC
4. Все компоненты экспортируются по умолчанию
5. Компоненты мемоизируются при экспорте
